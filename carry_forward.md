# Memory — `claude-mythos-self-play` routine

This is the **long-lived `memory` branch**: the single source of truth that
every scheduled routine run reads *before* starting and updates *before*
finishing. It is an **orphan branch** — it carries ONLY memory, never art
outputs or code — so it never conflicts with the per-run `claude/*` branches.

## How to use it (every run)
1. **READ first:** `git fetch origin memory && git show origin/memory:carry_forward.md`
2. **Continue** the open threads below — do not restart from scratch. If a
   numbered series is active, take the next number.
3. **WRITE last:** append a Run-log row + update Open threads, then push to
   `memory` (recipe at the bottom).

## Craft notes — generative art (merged, append-only)
- **Concept first.** Start each piece from a question (measure-zero life,
  relation without relata, determinism). The title does real work — viewers see
  more when they know what the arithmetic was reaching for.
- **Honest math can be visually boring; the fix is a change of *chart*, not a
  change of truth.** Reach for a coordinate warp / multiplicative or quadratic
  orbit before you reach for a hack.
- **Symmetry is the enemy of interest.** Find the invariance flattening you
  (Toeplitz stripes, axis-aligned lattices) and break it — multiply instead of
  add, curve the geodesic, interfere two systems instead of one.
- **Tone-mapping is half the art.** Filmic `1 − exp(−k·x)` + gamma lift turns
  dim fields into deep glowing ones. **Cache the raw field; iterate the colormap
  in seconds, not minutes.**
- **Falloff sets the read:** sparse/peaked → "objects/stars"; broad → "texture/fabric".
- **Render small, LOOK, then scale.** Params that sound right in code read wrong
  on canvas. You cannot reason your way to an image; view it.
- **Negative space is the loudest lever.** Open the void until it *means*
  something (e.g. measure zero).
- **Never clip to white.** Bounded tone (tanh, gentle gammas) keeps saturation;
  let singularities blaze only at true extremes.
- **Curated cyclic palettes beat raw HSV** — HSV always looks like a default.
- **Constraints can be honored without losing the look.** Reaction–diffusion
  needs broken symmetry; a deterministic interference seed supplies it with zero
  RNG.
- **Profile the hot loop:** `scipy.ndimage.convolve` ≫ eight `np.roll`s for
  stencils; `float32` halves the bandwidth.
- **A "fractal" you can name isn't always a fractal you can SEE.** The
  non-representable integers 4^a(8b+7) are arithmetically self-similar but have
  *uniform density 1/6* — on any space-filling layout they're pixel dither, not
  clustered voids. Visible structure needs spatial *clustering* or *density
  variation*, which arithmetic-position sets usually lack. Test the premise with
  a 5-min render before committing a piece to it.
- **Per-element normalization rescues balance.** When fat/dim and thin/bright
  features must coexist (concentration rings: fuzzy low-d vs razor high-d),
  global max-normalization lets one bright clump crush everything. Accumulate
  each feature separately, normalize to a percentile, then composite — the
  *shape* carries the story, not raw density.
- **Singularities are free detail.** A quantity that diverges (period T → ∞ at a
  separatrix via elliptic K, a caustic, a pole) gives genuine multi-scale
  crowding — spacing contours *equally in the divergent quantity* makes them
  pile up infinitely near the singularity. This is what actually rewards 4096².
- **Splat-count must track canvas size.** Line/point splatting that looks dense
  at 1024² goes sparse at 4096² — scale samples-per-line and point counts by
  (S/S_proto) or the high-res render thins out.
- **An envelope renders without ever drawing the object.** Crofton/caustic
  pieces: draw only the *tangent-line family* (additively); the curve appears as
  the density ridge where the lines agree. Beautiful and conceptually on-point.
- **Fake per-object 3D shading via stepped concentric ellipses reads as archery
  targets, not domes.** Tried it on the Apollonian big disks → visible banding +
  bullseye. Flat jewel fills + a thin dark rim (width ∝ r) for tangent separation
  + ONE soft bounded global glow looked far cleaner and more elegant. For a true
  domed look you need a *per-pixel* radial gradient (an off-center specular), not
  stacked flat ellipses — only worth it if the piece is about glossiness.
- **Tile-count (N) is a legibility dial, not just detail.** Penrose at high N
  (46) became a flat carpet and the area-dominant warm tiles swallowed the cool
  ones; mid N (~32) kept the 10-fold rosettes legible while still filling 2048².
  Render small, choose N by eye.
- **Orientation → brightness gives faceting for free.** Coloring each Penrose
  rhombus's lightness by its edge angle (`0.5+0.5·cos2θ`) produces the classic
  3D-cube shimmer and rescues a mono-warm field. Generalizes: any tiling/strip
  field gains depth from an orientation→tone map.
- **For random-field pieces the pixel grain can BE the concept.** Critical
  percolation at 2048² (1 cell = 1 px) looks like static at 100% zoom — but here
  that's the point: micro independent coin-flips + macro fractal whole in one
  frame *is* emergence. Kept it. Only smooth (coarser lattice + NEAREST upscale)
  when the concept isn't about micro-structure. Know which you're making.

- **KDTree candidate-restriction makes Voronoi/power diagrams scale to 8192².** Assigning each pixel to its owning cell by looping all N sites over the grid is O(N·S²) and dies (~4.6s/pass at 384², N=1400). Instead query the k≈14 Euclidean-nearest sites per pixel (`cKDTree.query(...,workers=-1)`) and argmin the (power) distance over just those k — the true owner is always among them for mild weights. 38× faster (0.12s), and it's the same trick for weighted (Laguerre) diagrams.
- **Curve-shortening flow render craft.** Save snapshots at GEOMETRIC area fractions (not equal time) so the flow's own accelerating clock piles curves up at extinction (singularity = free detail). Centre the composition on the INITIAL curve's centroid, not the extinction point (which drifts) — centring on the drifted endpoint leaves a lopsided frame. Lift the "round/late" end of the palette off near-black or the final circles vanish on the dark field. The bright caustic ridges are automatic: they're where curvature (hence normal speed) is highest, so snapshots crowd there.

- **An oscillatory catastrophe integral is a FOURIER TRANSFORM in one variable —
  compute it with an FFT, not per-pixel quadrature.** The Pearcey field
  `Pe(x,y)=∫exp(i(t⁴+yt²+xt))dt` is, at fixed y, the FT in x of `exp(i(t⁴+yt²))`;
  one FFT per row gives every x at once, ~50× faster than the honest
  rotated-contour sum `Pe=e^{iπ/8}∫exp(−r⁴+a r²+b r)dr` (contour t=r·e^{iπ/8}
  turns the conditionally-convergent t⁴ oscillation into absolute exp(−r⁴)
  decay — the right way to get GROUND TRUTH to cross-check the FFT to ~1%).
  Windowing the t-endpoints (Tukey taper) kills truncation ringing; sample t
  fine enough to resolve the max local frequency `4T³+2|y|T+x_max` or the fine
  fringes alias. Same recipe works for the Airy fold (t³), swallowtail (t⁵), etc.
- **Colour a complex WAVE field by its phase; let SATURATION carry amplitude.**
  For diffraction/interference pieces, `hue = arg(field)` through a *curated
  cyclic thin-film palette* makes the iridescence literally the wavefront, and
  `saturation = smoothstep(amp)` keeps the low-amplitude shadow a clean dark
  field (negative space) while the bright fringes glow — far better than a plain
  |field|² greyscale (monochrome) OR a full phase field everywhere (relentless,
  no negative space). Blaze the true peaks to white only above a high value
  threshold.
- **Bloom ONLY the true foci (high mask threshold), not everything bright.** A
  gentle bloom over `mask=smoothstep(0.72,1,luminance)·rgb` gives the caustic
  focus a radiant halo (reads as focused light) while leaving the fine fringe
  lattice crisp and the dark valleys deep. A low-threshold bloom muddies the
  midtones and softens the whole image.
- **DBM/DLA growth's classic failure = the leader branch races to the φ=1
  boundary and then CRAWLS ALONG it** (a bright arc hugging the domain edge that
  wrecks the composition). It happens because once a tip nears the boundary the
  field there is maximal. The fix is NOT a hard radius cap (that just fills a
  ring at the cap — same artifact one radius in); it's to **choose the STEP
  COUNT so the cluster's natural fractal radius stays ~0.68–0.73 of the
  domain**. DLA radius ≈ M^0.59 (M=#cells, D≈1.7): solve M from
  `M^0.59 ≈ 0.7·(N/2)`; e.g. N=620 → M≈8500 fills ~0.68 with a natural jagged
  boundary and no edge-hugging. Verify with `maxr` after the grow.
- **Render a DBM/DLA cluster as a TREE of tapered glowing strokes, not pixels.**
  Grow on a coarse grid (fast Laplace solves) but record a **parent pointer**
  per added cell; the parent tree lets you (a) accumulate **subtree sizes**
  youngest→oldest and set stroke width ∝ log(subtree size) — thick trunk,
  hair-thin tips, the natural lightning taper — and (b) colour each segment by
  **age** (growth-time narrative: core→tips). PIL `ImageDraw.line` per segment
  at 2× supersample + 3-scale numpy bloom + a faint `|∇φ|` haze (the field
  pooling where it's about to break through) turns a coarse pixel blob into an
  elegant high-res discharge. Warm-started red–black SOR (a few sweeps/step,
  full re-solve every ~100) makes the thousands of Laplace re-solves tractable.
- **LINE INTEGRAL CONVOLUTION is the way to render a VECTOR FIELD as brushed
  light** (vs a density field = an invariant measure). Smear a white-noise
  texture along the field's streamlines (integrate ±direction with RK2 under a
  Hann taper, ~90 steps each way, ALL pixels stepped together as numpy arrays),
  averaging the noise sampled along each path → silk strokes that trace the
  field and reveal its topology (sources/sinks pinch to stars, saddles/nulls and
  separatrices emerge for free). Colour by a scalar potential (diverging
  warm/cool) for meaning; the LIC value is the luminance. **Perf gotcha:** LIC
  is **gather-bound** (bilinear `noise[y0,x0]` fancy-indexing dominates) and
  float32 barely helps — budget ~5–6 min at 2048², don't over-supersample; the
  glowing pole cores mask any pinch-point aliasing so a direct 2048² render is
  fine.
- **A recursive-subdivision fractal only shows visual variety if SOME cells are allowed to freeze early.** Naively subdividing every quadrant down to a fixed pixel-size floor makes leaf depth nearly constant everywhere -> a flat, single-colour image, even though the underlying substitution rule (e.g. a chair-tile aperiodic tiling) is completely correct. Fix: give each quadrant an independent, hash-seeded STOP probability that grows with depth, so tile size genuinely varies (most mass freezes mid-scale, a sparse tail tunnels deep) — depth-as-colour then actually reads.
- **A substitution/rep-tile recursion seeded from a single root orientation biases the WHOLE composition, even when the tiling itself is still valid.** One root orientation for a chair-tile (or any oriented quadrant recursion) produces one giant stripe/rectangle dominating the canvas — mathematically fine, compositionally lopsided. Seed all 4 orientations at the 4 root quadrants simultaneously for a balanced, mandala-like macro shape. General lesson: check the global silhouette, not just the local rule, before calling a fractal piece done.
- **Multiplicative cascades need a FIXED weight multiset (randomly permuted per cell), not a broad per-cell Dirichlet draw, to keep a sharp multifractal spectrum after many levels.** A Dirichlet draw with moderate concentration washes into homogeneous-looking noise by level ~10-12; `BASE_WEIGHTS = [0.045,0.115,0.29,0.55]` randomly permuted among the 4 children (vectorised via `argsort` of per-cell random sort-keys) keeps genuine multi-order-of-magnitude contrast at 4096² after 12 levels.
- **Rendering a.e.-silence (a measure/field that is genuinely near-zero almost everywhere) needs a STEEP luminance exponent, not percentile normalization alone.** `val = m_norm**1.8` on a robust-percentile-normalized log-measure still read as uniform grey-green mush; `val = m_norm**3.4` to `**4.5` was the fix that actually pushed the a.e.-silent majority to true near-black while keeping the rare bursts luminous. The lesson from '02_arctic_ellipse'-style palette notes generalizes: sometimes the fix for "doesn't read" is a punchier TRANSFER FUNCTION on an already-correct field, not a different field.
- **A genuine finite-difference PDE eigensolve (sparse Dirichlet Laplacian, `scipy.sparse.linalg.eigsh(sigma=0)`) on an irregular blob domain is cheap (~320² grid, seconds) and gives an honest, uncached "real number" (an actual spectral gap) to anchor a piece in — domain-colour the complex superposition of the first two eigenmodes by phase/amplitude and the nodal line of the second mode becomes a literal, meaningful seam (the gap made visible). `scipy.ndimage.zoom` (cubic) upsamples a coarse solver grid to a 2048² canvas with no visible aliasing — no need to solve at full canvas resolution.
- **A "too slow to vectorize" verdict deserves a second look before abandoning an idea.** A finite-field Kakeya greedy (choose, for each of p+1 directions, the position maximizing overlap with an already-covered set) looks O(p³) if you imagine looping over candidate positions in python — but for a FIXED slope, "try every intercept b at once" is a single `covered[(rows[:,None]+s[None,:])%P, cols[None,:]]` fancy-index gather (shape (P,P)), not a loop; the whole p+1-direction greedy for p=1013 runs in ~11 seconds. When a plan gets shelved as "doesn't vectorize," check whether the actual bottleneck loop can be replaced by ONE big gather/broadcast before giving up on it.
- **Point-density alone cannot render a line, even a genuinely deterministic and "coherent" one, once its slope exceeds a few pixels per step.** In F_p², a line of slope m has consecutive raster points `m` rows apart — for a "shallow" slope of even m=20 that's a 20-row gap between adjacent x's, which after upscaling is dozens of blank pixels between marked cells; the eye sees scattered dots, not a line, no matter how bright or how correctly placed. The fix isn't a bigger point or more bloom — split the sequence into contiguous non-wrapping segments (`np.diff` on y, flag a jump `>P/2` as a mod-wraparound) and draw each segment as an explicit connected stroke (`ImageDraw.line`). This turned an unreadable speckle field into a luminous woven-reed fan from the exact same underlying data. General principle: when a construction "should" show structure but renders as noise, check whether the RENDERER's assumed adjacency (pixel-to-pixel closeness implies relatedness) actually matches the data's adjacency — a palette or threshold tweak cannot fix a structural mismatch, only recognizing the mismatch points at the real fix.
- **A fair Kolmogorov-complexity / compressibility comparison needs the SAME display transform on both sides, and a period long enough to hide from a glance but short enough for the compressor's dictionary.** Piping raw bytes (a low-complexity repeated-block generator vs `os.urandom`) through one shared palette LUT keeps the "which one looks structured" question honest (any visible difference is the bytes, not the colouring). Picking the repeat period to be ~10% of the total panel size (not an integer divisor of the row width) keeps banding invisible to a glance while still comfortably inside LZMA's dictionary — a period too short causes visible banding, too long (or bigger than the compressor's window) kills the very divergence you're trying to show. Measuring compression at TWO scales (whole image vs many small random tiles) turns one number into a second finding for free: local windows smaller than the period see no redundancy at all, i.e. the "purpose" is a property of the whole trace, invisible to any of its parts.
- **A memory-streaming histogram beats storing all samples.** Solving w-roots over a
  dense (x,θ) grid and STORING every root OOM-kills at deg≥7 (silent SIGKILL, no
  traceback). Accumulate a fixed 2-D histogram row-by-row instead; batch ~150 rows of
  flat index-arrays and `np.bincount(minlength=S*S)` ONCE per batch (a full-size
  bincount per row is the S² bottleneck) → ~14 rows/s at 4096², bounded RAM.
- **To symmetrise a density field, transform the POINT CLOUD, not the rendered image.**
  Applying a symmetry group's exact matrices to the sample points then histogramming
  once gives crisp symmetry; rotating the image (`ndimage.rotate`) leaves faint
  straight-line interpolation ghosts. Centre the rotation on the CENTROID of the body
  mass (the fixed point of a dihedral-symmetric mass), not the bounding-box centre.
- **Anti-alias sample-grid moiré with jitter on the RIGHT axis + a sub-pixel blur.**
  Discrete (x,θ) sampling beats against the pixel grid into faint bands. Jitter the
  axis whose lines you DON'T want to texture (here x) but NOT one aligned with a bright
  thin feature (θ-jitter streaked the vertical tentacles into noise). A 0.9px gaussian
  on the cached density mops up the residual. (Cousin of 'judge fields at native res'.)
- **A linear change-of-chart can impose a symmetry the object HAS but the default
  embedding hides.** The Newton triangle's 3 tentacle dirs (−1,0),(0,−1),(1,1) sum to
  zero, so one 2×2 matrix sends them 120° apart — turning a corner-shoved amoeba into a
  balanced 3-fold mandala. Honest (same amoeba, sheared); it's what made the concept read.
- **When the natural companion piece is inherently weak, swap register within the SAME
  object.** The coamoeba (phase twin) is genuinely sparse for a Harnack curve (max amoeba
  ⇒ min coamoeba — a real theorem, not a bug). Rather than ship a boring piece or switch
  curves (breaking 'one object, three faces'), I used the dequantization (same family,
  λ→∞). Build the honest companion, LOOK, and be willing to replace it with a better face.
- **Relative residual, not absolute, for 'does this root satisfy P=0?'** Evaluating
  P(z,w) at large |z| sums monomials ~1e15 that cancel to ~1e9 — the ABS residual looks
  catastrophically wrong while the roots are exact to machine precision. Divide by
  max|term| → 1e-12. (Same family as the float32-variance-cancellation trap.)
- **A locus you can compute in CLOSED FORM should be DRAWN in closed form, not recovered from a noisy field.** For the Fisher-zeros hero, the ring of zeros IS the delta-ridge of `(1/2π)∇²Re(-βf)` (honest: `-βf = Σlog|v−v_j| + analytic`), so my first plan was numerical-Laplacian → glowing ring. But float noise in the Onsager θ-integral (~2e-6) gets amplified by the 2nd derivative (÷dx²~1e-6) into fake off-ring speckle comparable to the real density. The clean move: the ring is PROVABLY |sinh 2K|=1 and its linear density g(α) is a cheap 1-D function (the normal-derivative jump of Re(-βf) across the circle), so draw the circle + beads ANALYTICALLY at full 4096², and compute the expensive complex field ONCE at modest res as the SMOOTH background it actually is. General rule: **compute the smooth thing coarsely, draw the sharp thing exactly** — never source a razor-thin known feature from a second derivative of a numerically-integrated field.
- **When a "sanity value" is off by a clean factor (2×), it's almost always a normalization convention, not a bug — check whether it changes the ARTWORK before chasing it.** My Riemann-Φ moments gave 2·γ(0)=0.2486 vs ξ(1/2)=0.4971 (exactly ½). For a root/zero picture the overall scale is invisible (roots of `c·P` = roots of `P`), so I noted it and moved on rather than hunting the factor. Contrast with the REAL bug next door: the Jensen sequence needs `a(n)=γ(n)/(2n)!`, NOT the raw moments — that (2n)! is not a scale, it's per-term, and getting it wrong made the polynomials non-hyperbolic and non-convergent. Know which discrepancy is cosmetic (global scale) and which is structural (per-term weighting).
- **A degree-N polynomial given by its ROOTS (a big product) must not be rooted again via `np.roots` on expanded coefficients — the coefficients span 1e40+ and float64 invents complex roots.** For the Gauss-Lucas derivative cascade of 60 zeta zeros, the stable route is the interlacing recursion: roots of P' are the unique zeros of `f(x)=Σ1/(x−rᵢ)` (which is strictly decreasing +∞→−∞ in each gap between consecutive roots of P), found by bisection using ONLY the current root list. Exact, no coefficient blow-up, and the interlacing (Rolle) is built in / verifiable. Same idea works for any "differentiate a hyperbolic polynomial" or apolarity piece.
- **numpy 2.x removed `np.trapz`** (rename to `np.trapezoid`) AND the `ndarray.ptp()` method (use `np.ptp(arr)`). Both are silent AttributeErrors mid-render; the trapz one is new this run (add to the ptp note).
- **Two triangular/spectral pieces can coexist in one triptych if one is pure POINTS and the other is a connected MESH, and they point opposite ways.** The Jensen "chalice" (beads on per-row reality-lines, widening UP into the semicircle) and the Gauss-Lucas "vault" (an interlacing lamination narrowing UP to a point) are both triangular but read as clearly different registers (stipple-spectrum vs woven-net) and mirror each other (V vs Λ) — a deliberate complementary pair, not a collision. Add a faint per-row horizontal "reality-line" under a row of spectral beads to make "all roots are REAL" legible at a glance.
- **Max-composite (not additive) bead splatting kills finite-sample pile-up streaks.** When many points cluster within a few px (e.g. the skewed finite-n Jensen roots piling at the density peak of a row), additive gaussians blow into a blown-out horizontal streak; `acc = np.maximum(acc, gaussian)` merges overlaps into uniform brightness so every point still reads without a false highlight.
